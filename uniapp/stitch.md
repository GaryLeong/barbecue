**烧烤点餐小程序设计文档（精简版）**

**一、项目概述**

1. **目标**：开发支持“堂食+外卖”的烧烤微信小程序MVP，聚焦SKU复杂、口味定制、酒水关联、夜宵场景。
2. **核心痛点**：
    - 按串/份计价，多口味/规格组合。
3. **风格**：暖色夜市风，简洁实用，无冗余设计。

**二、核心功能模块**

1. **首页**
    - 模块：轮播图（爆品/活动）、点餐模式切换（堂食/外卖）、必点招牌、酒水专区
2. **点单页**
    - **布局**：左右联动（左侧双维度分类：食材/做法；右侧商品卡含起售量、单位、口味Tag）。
    - **规格选择**：弹窗支持口味多选（微辣/特辣等）、加料备注（如多葱、免香菜）。
    - **购物车**：悬浮栏显示总价/串数，展开面板按口味分组显示，支持凑单提醒。
3. **订单页**
    - 列表：突出桌号、总串数、辣度汇总，支持催烤、加菜（堂食）。
    - 详情：按口味分组展示商品，配送订单显示骑手位置和保温状态。
4. **我的页**
    - 用户信息：累计撸串数、会员等级。
    - 功能：优惠券（区分酒水/全场券）、钱包（含押金记录）、地址管理（夜宵备注模板：放门口等）。

**三、技术架构**

1. **后端**：Spring Boot + MySQL（SKU表设计支持多对多口味关联）+ Redis（缓存/防超卖）。
2. **前端**：Uni-app（Vue3 + TS，跨端适配，分包优化主包<1.5MB）。
3. **AI辅助**：代码生成（脚手架、CRUD、复杂交互）、正则/SQL编写、代码审查。
4. **关键逻辑**：
    - 购物车：Pinia/Vuex Store管理“同品异规”数据。
    - 支付：微信支付V3（防篡改校验、回调幂等性）。
    - 后厨：订单推送至打印机或KDS系统（预留接口）。

**四、视觉规范**

1. **主题色**：深色背景+暖橙/红点缀（营造烟火气）。
2. **图标/组件**：烧烤相关图标（烤串、啤酒、火炉），按钮突出夜宵元素。
3. **暗黑模式**：默认深色，可选浅色适配白天。
4. **UI建议**：购买现有餐饮模板微调，避免自行设计耗时。

**五、交付物清单**

1. 项目目录结构 + `app.json` 配置。
2. 核心组件：SKU规格选择器、左右联动+口味弹窗。
3. 购物车数据模型与状态管理代码。
4. 接口文档（含规格、口味、支付回调定义）。
5. 烧烤Mock数据（真实菜品、多规格示例）。

**六、开发建议**

1. **分步开发**：
    - 阶段1：基础框架、登录、菜单展示。
    - 阶段2：点单核心（规格选择、购物车）。
    - 阶段3：支付、订单、后厨对接。
2. **测试重点**：
    - 高并发下单防超卖。
    - 弱网环境数据缓存。
    - 支付全链路自测。
3. **扩展预留**：
    - 多人同桌扫码合并订单（WebSocket实时同步）。
    - 优惠券叠加、会员系统（二期）。
4. **运维**：服务器部署Docker化，HTTPS配置。

**七、避坑提示**

1. 数据库设计优先：SKU与口味多对多关系，避免JSON硬编码。
2. 警惕AI代码“幻觉”，支付/安全逻辑必须核对官方文档。
3. 保持MVP范围，砍掉非核心功能（如第三方配送）。
